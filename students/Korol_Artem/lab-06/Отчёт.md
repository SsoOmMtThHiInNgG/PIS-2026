# Цель работы

Разработать комплексную стратегию тестирования программного обеспечения, включающую модульные (Unit), интеграционные (Integration) и End-to-End (E2E) тесты для сервиса управления мероприятиями и билетами.

---

# Вариант №15 — Сервис управления мероприятиями и билетами 🎫

**Питч:** Пользователь может находить мероприятия, просматривать расписание и оформлять билеты.

## Ядро домена

* Events (мероприятия)
* Tickets (билеты)
* Schedules (расписание)
* Speakers (докладчики)

# Ход выполнения работы

## 1. Unit-тестирование

Unit-тесты предназначены для проверки отдельных компонентов системы без взаимодействия с внешними зависимостями.

### Реализованные тесты

* TicketTest
* CreateTicketHandlerTest
* PublishEventHandlerTest
* GetEventScheduleHandlerTest
* SearchEventsHandlerTest

### Проверяемые сценарии

* создание билета;
* публикация мероприятия;
* получение расписания;
* поиск мероприятий;
* работа доменной модели билета.

## 2. Интеграционное тестирование

Интеграционные тесты предназначены для проверки совместной работы нескольких компонентов системы.

### Реализованный тест

```text
EventRepositoryIntegrationTest
```

### Проверяемые сценарии

* сохранение мероприятия;
* получение списка мероприятий;
* взаимодействие доменной модели и репозитория.

### Скриншот

Вставить изображение:

```text

```

---

## 3. End-to-End тестирование

E2E-тесты проверяют полный пользовательский сценарий работы системы.

### Реализованный тест

```text
EventFlowE2ETest
```

### Сценарий тестирования

1. Создание мероприятия.
2. Публикация мероприятия.
3. Создание билета.
4. Проверка результата.

### Проверяемые компоненты

* Domain Layer
* Application Layer
* Infrastructure Layer
