## Цель работы

Реализовать архитектурный паттерн CQRS с разделением Write Model и Read Model для системы управления мероприятиями и билетами.

---

## Вариант №15 — Сервис мероприятий и билетов

**Питч:** Пользователь может создавать мероприятия, публиковать их и приобретать билеты.

**Ядро домена:**

* Мероприятия (Event)
* Билеты (Ticket)
* Расписание (Schedule)
* Докладчики (Speaker)

---

## Ход выполнения работы

### 1. Write Model

Write Model отвечает за изменение состояния системы.

Были реализованы агрегаты:

* EventAggregate
* TicketAggregate

Команды:

* CreateTicketCommand
* PublishEventCommand

Обработчики команд:

* CreateTicketHandler
* PublishEventHandler

Доменные события:

* EventPublishedEvent
* TicketCreatedEvent
* TicketActivatedEvent
* TicketCancelledEvent

---

### 2. Read Model

Read Model отвечает за получение данных без изменения состояния системы.

Были реализованы представления:

#### EventView

Содержит:

* идентификатор мероприятия;
* название мероприятия;
* статус публикации.

#### TicketView

Содержит:

* идентификатор билета;
* идентификатор мероприятия;
* статус билета.

---

### 3. Event-Driven Sync

Для синхронизации Read Model используются проекции.

Реализованы:

#### EventProjection

Обрабатывает событие:

```java
EventPublishedEvent
```

и обновляет представление мероприятия.

#### TicketProjection

Обрабатывает события:

```java
TicketCreatedEvent
TicketActivatedEvent
TicketCancelledEvent
```

и обновляет представление билета.

Пример обработки события:

```java
public void handle(
        TicketCreatedEvent event
) {

    TicketView view =
        new TicketView(
            event.getTicketId(),
            event.getEventId(),
            "CREATED"
        );

    repository.save(view);
}
```
