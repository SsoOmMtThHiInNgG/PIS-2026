# 4. Docker Compose

Для запуска приложения и базы данных использовался Docker Compose.

## docker-compose.yml

```yaml
version: '3.8'

services:

  app:
    build: .
    container_name: events-app

    ports:
      - "8080:8080"

    environment:
      SPRING_DATASOURCE_URL: jdbc:postgresql://db:5432/events
      SPRING_DATASOURCE_USERNAME: postgres
      SPRING_DATASOURCE_PASSWORD: postgres

    depends_on:
      - db

  db:
    image: postgres:15

    container_name: events-db

    environment:
      POSTGRES_DB: events
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres

    ports:
      - "5432:5432"
```

# Контрольные вопросы

## 1. Почему Repository находится в Infrastructure Layer?

Repository относится к инфраструктурному слою, так как отвечает за хранение данных и взаимодействие с базой данных.

---

## 2. В чём преимущество ORM?

ORM позволяет:
- работать с объектами вместо SQL;
- автоматически выполнять маппинг;
- уменьшать количество SQL-кода;
- упрощать поддержку приложения.

---

## 3. Зачем использовать Docker Compose?

Docker Compose позволяет:
- быстро запускать несколько сервисов;
- автоматически поднимать PostgreSQL;
- стандартизировать окружение разработки.

---

## 4. Почему REST Controller не должен работать напрямую с Domain?

Контроллер должен обращаться к Application Layer, чтобы соблюдать принципы Clean Architecture и разделение ответственности.
