## Цель работы

Разбить монолитное приложение на независимые микросервисы с использованием асинхронного взаимодействия через Event Bus.

---

## Вариант №15 — Сервис мероприятий и билетов 🎫

**Питч:** Пользователь может создавать мероприятия, публиковать их и приобретать билеты.

**Ядро домена:**

* Мероприятия (Event)
* Билеты (Ticket)
* Расписание (Schedule)
* Докладчики (Speaker)

---

## Ход выполнения работы

### 1. Event Service

**Bounded Context:** Управление мероприятиями

**API:**

* GET /events
* POST /events

Сервис отвечает за хранение информации о мероприятиях, расписании и докладчиках.

---

### 2. Ticket Service

**Bounded Context:** Управление билетами

**API:**

* GET /tickets
* POST /tickets

Сервис отвечает за создание и обработку билетов на мероприятия.

---

### 3. Notification Service

**Bounded Context:** Уведомления

Сервис получает сообщения из RabbitMQ и обрабатывает события системы.

---

### 4. Event Bus (RabbitMQ)

**События:**

* EventPublishedEvent
* TicketCreatedEvent
* TicketActivatedEvent
* TicketCancelledEvent

**Скриншот RabbitMQ Management:**

![RabbitMQ](./rabbit.jpg)

---

### 5. API Gateway

**Маршрутизация:**

* `/events/**` → Event Service
* `/tickets/**` → Ticket Service

**Конфигурация:**

```nginx
events {}

http {

    upstream event_service {
        server event-service:8080;
    }

    upstream ticket_service {
        server ticket-service:8081;
    }

    server {

        listen 80;

        location /events/ {
            proxy_pass http://event_service;
        }

        location /tickets/ {
            proxy_pass http://ticket_service;
        }
    }
}
```

---

### 6. Docker Compose

Для запуска микросервисов использован Docker Compose.

В состав системы входят:

* Event Service
* Ticket Service
* Notification Service
* RabbitMQ
* API Gateway

## Вывод

В ходе выполнения лабораторной работы была выполнена декомпозиция монолитного приложения на независимые микросервисы. Были выделены Event Service, Ticket Service и Notification Service, каждый из которых отвечает за собственный bounded context.

Для организации асинхронного взаимодействия между сервисами был использован RabbitMQ в качестве Event Bus. Для маршрутизации входящих запросов реализован API Gateway на базе Nginx. Полученная архитектура обеспечивает независимость сервисов, упрощает масштабирование системы и соответствует принципам микросервисного подхода.
